## Repaired distinctions

The old server, client, web server and database server records already had
hardware genera. Their labels now state that physical meaning. Workstation
is qualified as a computer. Existing request capabilities, monitoring and
web-application relations remain unchanged. The two physical network roles
also receive the network-host genus. A duplicated reverse mutual-role row
with an unsupported 95 percent value is rejected; the original unspecified
mutual-role assertion remains.

Separate software families cover server, client, database and file services.
The existing HTTP client/server software records are reused under the new
role families, retaining their valid direct software genera. Generic request
operations permit local communication; existing network operations remain
narrower. [PostgreSQL's architecture documentation](https://www.postgresql.org/docs/18/tutorial-arch.html)
supports distinguishing the database service program, client program and
host. [MDN's web-server explanation](https://developer.mozilla.org/en-US/docs/Learn_web_development/Howto/Web_mechanics/What_is_a_web_server)
distinguishes hardware and software meanings.

Jenkins previously inherited hardware server. It now belongs to automation
server software, with purposes covering build, test and deployment
automation, following the [Jenkins documentation](https://www.jenkins.io/doc/).
The existing build record is qualified as a process. Automating an activity
and executing that activity are not assigned the same genus. No test suite
or development pipeline was run by this data batch.

HTTP client and server are connection-specific roles. The HTTP-to-HTTP
intermediary has both genera. The general reverse proxy does not: its
backend may use another protocol. Only the restricted HTTP-to-HTTP reverse
proxy gains both HTTP endpoint genera. User agents include automated
crawlers as well as browsers, without requiring live human interaction.
These distinctions follow [RFC 9110, sections 3.3–3.7](https://www.rfc-editor.org/rfc/rfc9110.html#section-3.3).

HTTP cache components are separate from response data, memory hardware and
the caching operation. Private and shared caches refer to the number of
users they serve; private is not a secrecy guarantee. Caching is optional.
A forward proxy with a shared cache is both a forward proxy and
cache-enabled software, with a shared-cache component. This uses the
[RFC 9111 cache distinctions](https://www.rfc-editor.org/rfc/rfc9111.html#section-1)
without importing a cache implementation or header policy.

The client-server architectural style is distinct from an architecture
using it. REST receives the narrower-style relation supported by
[Fielding's derivation](https://ics.uci.edu/~fielding/pubs/dissertation/rest_arch_style.htm#sec_5_1_2).
There are 21 new non-genus relations: purposes, operation targets,
components and corresponding roles. File-serving purposes are supported by
the [Samba project's description](https://www.samba.org/samba/what_is_samba.html).
