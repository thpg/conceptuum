## Evidence and scope

The type/value distinctions follow
[JLS types and values](https://docs.oracle.com/javase/specs/jls/se25/html/jls-4.html),
[Python built-in types](https://docs.python.org/3/library/stdtypes.html), and
[NIST's string entry](https://xlinux.nist.gov/dads/HTML/string.html).
Character representation is language-specific: a character type need not hold
exactly one abstract Unicode character. String length counts positions in the
selected sequence; repeated symbols still count, and an empty string has length
zero. No universal byte size, immutability, or encoding is attached to strings.

The character sense follows the distinctions between text units, glyphs,
graphemes, and code units in
[Unicode 17, chapter 3](https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-3/).
The LF/CR corrections use [Python lexical notation](https://docs.python.org/3/reference/lexical_analysis.html).
The two-character spellings `\n` and `\r` are notation aliases; no literal
newline is inserted into a term. Keyword/token classifications follow
[JLS lexical structure](https://docs.oracle.com/javase/specs/jls/se25/html/jls-3.html).
Byte ordering follows the separate layout controls documented in
[Python struct](https://docs.python.org/3/library/struct.html).

The integer-type interpretations use Microsoft's
[DWORD definition](https://learn.microsoft.com/en-us/windows/win32/winprog/windows-data-types)
and [QWORD definition](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-dtyp/ac050bbf-a821-4fab-bccf-d95d892f428f),
plus [Apple's UInt8 documentation](https://developer.apple.com/documentation/swift/uint8).
The UInt8 record denotes the reviewed unsigned eight-bit type meaning; this
does not identify every similarly named library type or add Swift-specific
methods to it. General width/range properties remain pending.
The real/rational/integer hierarchy follows
[OpenStax real numbers](https://openstax.org/books/college-algebra-2e/pages/1-1-real-numbers-algebra-essentials).
The ambiguous fractional adjective 4824 is not silently turned into rational number.

Computer-address classifications interpret the location-designating values in
[IBM address expressions](https://www.ibm.com/docs/en/zos/3.1.0?topic=testauth-address-expression),
[IBM indirect addresses](https://www.ibm.com/docs/en/zos/2.5.0?topic=testauth-indirect-address),
and [Microsoft return addresses](https://learn.microsoft.com/en-us/cpp/intrinsics/returnaddress).
Numeric, symbolic, virtual, and physical representation details are not collapsed
into one storage implementation. A return address is not the address of the
location storing that return address.

Regex purpose and patient links are ontology interpretations of
[Python regular-expression matching](https://docs.python.org/3/library/re.html).
Regex denotes a pattern rather than its source string or compiled object.
Processing roles follow [Flink's introduction](https://nightlies.apache.org/flink/flink-docs-stable/docs/learn-flink/overview/)
and [execution modes](https://nightlies.apache.org/flink/flink-docs-stable/docs/dev/datastream/execution_mode/).
Stream processing is not asserted to require unbounded input or a particular
engine. Processing input data is not encoded as a causal claim that every
execution produces new information.

## Context, coverage, and limits

All existing home contexts are preserved. IT assertions use U3. Real,
rational, and integer values have explicit U1 and U3 paths; U2 remains empty.
The manifest fixes a cohort of 30 existing records, with no merges. Its direct
non-taxonomic relation coverage changes from 0/30 to 2/30; 3/8 new concepts
have such a relation. All cohort and new concepts have Latin-script English
terms. This measures coverage, not full semantic correctness.

The pilot estimate increases from 25 to 33 new meanings: two missing types
needed a separate identity, and six missing shared concepts support reviewed
hierarchies or properties. This is not a quota. Continue by reusing and enriching
existing meanings where possible.

The following remain pending: `void` conventions, signedness and numeric
range properties, character codes/encodings, wide characters, Map, heap, event
listeners, mutex, nonexecutable statements, program listings, variable-length
fields, and Z-buffering. No type-to-value membership relation or arbitrary
bit-width property is invented to increase edge counts. Other children of the
classification, value, sign, and computing-process roots still need review.
